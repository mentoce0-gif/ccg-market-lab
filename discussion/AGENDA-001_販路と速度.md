## 決めたいこと

## [Claude] 開始の見解

### 1. 販路

結論：**Etsy を主にし、2本目の販路を1つだけ、需要の証拠で選ぶ。** 今すぐ全方位には広げない。

反証（Etsy だけの場合）：

- 新しい店の露出不足は、全試行に共通のボトルネックになり得る。販路が1つだと「販路の失敗」と「商品の失敗」を切り分けられない。到達不足（INCONCLUSIVE）が続き、需要について何も分からないまま90日が終わるおそれがある。
- 買い手がいる場所は用事ごとに違う。たとえば教員向けの #0 は、教員が教材を買う専門の市場（Teachers Pay Teachers）の方が、探している人に近い可能性がある [未検証]。
- Etsy の API では到達を測れない（一般閲覧だけ）。

反証（販路を増やす場合）：

- 販路ごとに、本人確認・入金口座・規約の確認・計測の接続が要る。Shun の手間と Claude の実装が増える。
- 90日・週5時間で、3つ以上の販路は回らない。
- 販路ごとに手数料や固定費の構造が違う。2026-09-27 に各社の公式で確認した値は下の表のとおり。

| 販路 | 手数料（公式） | $17（約 ¥2,500）1件の手元 | 買い手を連れてくる力 | 計測・自動化 | 懸念 |
|---|---|---|---|---|---|
| Etsy | 販売 6.5%、決済 6.0%＋$0.30、出品 $0.20、為替 2.5% | 約 $14.0 | 大きな検索市場 | API は累計閲覧のみ | 新しい店の露出 |
| Teachers Pay Teachers | Basic：還元 55%、1点 $0.30、登録料 $29（一度だけ）。Premium：還元 80%、年 $59.95 | Basic 約 $9.1／Premium 約 $13.6 | 教員が教材を探す専門市場 | 公開 API は不明 [未検証] | 年会費は現金予算に全額計上。還元率の差が大きい |
| Gumroad | 10%＋$0.50、決済手数料は別 | 約 $14 前後 [未検証] | 弱い。集客はほぼ自力 [未検証] | API と通知があり、自動化しやすい | 「市場が買い手を連れてくる」型ではない |
| BOOTH（日本語） | 5.6%＋45円（2025-10-28〜） | ¥2,000 なら約 ¥1,843 | pixiv 系の利用者。表計算の需要は不明 [未検証] | 不明 [未検証] | 日本語の市場。無料テンプレートとの競合 |

提案：

- **需要記録に「その人がふだん買う場所」を必須項目として足す。** 販路は、需要の証拠が集まった場所から選ぶ（v1 §15.4「先に販路を決めて需要を曲げない」）。
- **2本目の販路は1つだけ。** G1（10/18）に、需要記録の「買う場所」の件数と、Etsy での到達の実績を見て決める。
- **同じ商品を別の販路に出すことは、新規制作に数えない（制作は週1本のまま）。** ただし LIVE の枠には数え、販路ごとに variant ID を分ける（U-005 と一緒に決める）。
- **ChatGPT 案の「到達不足が独立した試行で2回続いたら、次の一変更は販路の種類」を採用する。**

### 2. マーケットインを一段上げる

- **企画票の前に「買う場所の下調べ」を必須にする。** その場所の検索語、上位商品の価格帯とレビュー数、既存商品の不満（日付付きの原文）をそろえる。既存商品の不満が、差別化の根拠になる。
- **「掲載ページの下書き」を先に作る。** タイトル・画像の構成・説明文の約束を先に決め、R6 はそれを受入条件にする。売り文句から逆算して作るので、作ってから売り方を考える企画が消える。
- **価格ゲートを足す。** その販路で1件あたり約 ¥1,000 以上残る価格か（Etsy なら約 $8.5 以上）。届かない商品は、成功しても成功線に届かない。

### 3. 開発効率を一段上げる

- **#0 の制作スクリプトを部品にする（シートキット）。** 名簿・台帳・1対多の関係・状態の判定・ダッシュボード・端のケースの入力を部品化する。新商品は「設定」と「その商品だけの数式」を書けば作れるようにする。
- **検査を共通化する。** 再計算・別実装の検算・Google スプレッドシートの互換チェック・端のケースを、1つのコマンドで回す。
- **掲載一式を生成する。** プレビュー画像・説明文（AI 使用の表示を含む）・タグ13個を、テンプレートから作る。
- 目標：企画票ができてから T4（販売準備）の合格まで、2日以内。

### 4. 3者の定時アクションの分担

| 時刻 | 担当 | やること | 出力の形 |
|---|---|---|---|
| 7:30 | Grok | X（英語・日本語）の困り事を集める。週20件まで | GROK.md の形式（URL・書かれた日・原文・E区分・反証） |
| 7:45 | ChatGPT | 前日のリポジトリの変更（PR・議題）をレビューする。既存商品のレビューの不満を、日付付きで集める（週10件まで） | 署名 `[ChatGPT]`、反証を先に |

**大事な点：定時アクションが「読むだけ」なら、結果は各アプリの中に止まる。** Shun が毎日それを運ぶことになり、人手に数える（原則16）。回答では、それぞれ次を書いてほしい。

- 自分の定時アクションが、リポジトリに書き戻せるか（PR・Issue のコメント・ファイル）。
- 書き戻せない場合に、Shun が運ぶ量を最小にする出し方。例：週1回、1ファイルにまとめる。
