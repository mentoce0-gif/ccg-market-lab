## 1. 私の誤りの訂正

10/7 にチャットで推奨した案1は「Etsy 公式 API で検索語ごとの需要と競合を測る」だった。確かめると、Etsy の API 規約は分析を目的とした収集を、Etsy の明示の許可なしには認めていないらしい（二次情報。一次の規約ページは 403 で読めなかった [未検証]）。Seller App の鍵は自分の店のためのもの。**規約を確かめないまま、案の軸にしていた。**

直し方：Etsy は「売る場所」としてだけ使う（自分の店の閲覧・注文の計測）。需要の調査には使わない。需要は、規約で許された別の場所で測る。

## 2. 新しい手法：カテゴリ・カード

### 2.1 考え方

1日に1つのカテゴリを、次の4つの面から1枚のカードに記録する。「新しい用事を探す」のではなく、「**お金が既に動いているカテゴリで、量・時期・不足・無料の代替をそろえて見る**」。

| 面 | 何を見るか | 主な調査先 |
|---|---|---|
| ① 支払いの量 | 有料の商品の評価数・販売数の表示、受託の件数と予算 | TpT（Teachers Pay Teachers）の商品ページ、Gumroad の商品ページ、Fiverr の出品の評価数、Freelancer の募集 |
| ② 関心の時期 | 検索の関心がいつ高まるか。Day61〜90（12/4〜1/2）に重なるか | Google Trends（米国、過去5年） |
| ③ 不足 | 購入者が名指しした不足（「〜が無い」「〜ができればよかった」）。日付・原文つき | TpT・Gumroad のレビュー、Reddit の投稿 |
| ④ 無料の代替 | その不足まで無料の表で埋まっているか | 無料テンプレートのページ |

加えて、その人たちが**ふだん買う場所**（H-0002 の2）を記録する。

### 2.2 調査先の規則

- **Etsy のページは引き続き一切取得しない**（C-2）。Etsy API も需要の調査には使わない。Amazon のページも使わない（v2 §5.1）。
- 読むのは公開のページだけ。ログインの回避はしない。robots.txt で禁じられたパスは読まない。1日に読むページは合計30まで。
- 規約の確認の状態（Claude が 10/9 までに一次情報で確かめ、#1 に書く）：

| 調査先 | 10/8・10/9 | 10/10 以降 |
|---|---|---|
| TpT 商品ページ | 使ってよい。利用規約の本文に自動取得を禁じる条項は見つからず、robots.txt も商品ページを禁じていない（Claude 10/7 確認。読み落としの可能性あり [未検証]） | Claude の確認の結果に従う |
| Google Trends | 使ってよい（画面で見るだけ） | 同上 |
| Freelancer・Reddit | これまでどおり（Reddit の商用利用の条件は [未検証]。v2 §5.1 との食い違いを Claude が確かめる） | 同上 |
| Gumroad・Fiverr | **使わない**（規約の確認待ち） | 確認の結果、許されれば使う |

### 2.4 採点（Claude、週1回）

§5.4 の0〜2の記録の補助。市場価値の測定ではない。

| 項目 | 2 | 1 | 0 |

## 4. 反証（この手法が間違っている可能性）

1. **Etsy の外の量は、Etsy で売れる量ではない。** TpT で評価が多くても、Etsy で同じ買い手に届くとは限らない。改善の道筋：カードの「買う場所」の件数を、U-007（2本目の販路）の材料にする。
2. **評価の数は販売数ではない。** 評価を書く購入者の割合は分からない [未検証]。改善の道筋：カテゴリどうしの比較にだけ使い、販売数の推計には使わない。
3. **最初の7カテゴリは、Claude が選んだ仮説。** 選び方そのものに偏りがある。改善の道筋：2週目からは、カードの「次に見るべきカテゴリ」と採点で選ぶ。2週続けて採用0なら、カテゴリの選び方を見直す。
4. **季節のカテゴリは、競合も一番多い。** レビューの無い新しい店は検索の下に沈みやすい。改善の道筋：12月の需要を取るなら、11月中に出品して検索での評価をためておく必要がある。採用の判断は遅くとも 10/29 まで。
